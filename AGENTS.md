# Frontend agent notes

- Read [`README.md`](README.md) and [`docs/DECISIONS.md`](docs/DECISIONS.md) before architectural, review or coordinated work. Also read [`update_plan.md`](update_plan.md) for current follow-up work; dated reviews are historical evidence, not instructions to apply unchanged. Setup and current API contracts live in [`DEVELOPMENT.md`](DEVELOPMENT.md). The former workspace `Context.md` and `WORKSPACE.md` are absent from this checkout and are not prerequisites.
- Treat the frontend and backend as one co-delivered application. Keep frontend code focused on components, layouts, navigation, presentation, interaction state, API orchestration, and inline form feedback. Do not duplicate business rules or authoritative validation from the backend; render its canonical `ApiError` instead. TypeScript transport types describe the internal API boundary and are not a separate frontend business model.
- Preserve the documented decisions: `useExecute` is legacy, success/reset/navigation remains the current convention, and the deliberately limited `window.error` component must not be automatically replaced by a React boundary. Browser tabs do not share a JavaScript store; distinguish this from overlapping requests within one store. Revisit decisions on concrete evidence or an explicit new need, not an old review alone.
- Keep review claims proportional to evidence and context. A capability not yet demonstrated on complex applications is not a proven inability; a bootstrap backend is not judged against unspecified banking requirements. Neither distinction excuses a reproduced functional defect.
- Inspect this repository's status before and after work. Preserve existing changes, do not stage or commit unless requested, and keep `dist/` disposable.
- Keep tracked text in LF with a final newline, as declared by [`.gitattributes`](.gitattributes) and [`.editorconfig`](.editorconfig). Do not reintroduce CRLF or missing-final-newline comparator noise.
- Files under `src/modele/rh` and `src/modules/rh` are generator-shaped. Correct repeated patterns in `../engine` first, run the engine from its root, review `engine/result/fe`, and selectively transfer changes without overwriting runtime customizations.
- `src/modele/admin/account` and `src/modules/admin/account` also start from the engine's generated Account candidate. Preserve their hand-maintained security-contract adaptations: `/api/admin/accounts`, distinct create/update/reset request shapes, canonical `id` navigation, role presentation, self-update feedback, password reset, root redirect, and absence of deletion. Never transfer the generated Account backend over `crud-be`'s security implementation.
- Page-scoped generated `Req*` and `Res*` interfaces aggregate several actions. Keep strict service inputs such as route identifiers, command `request` payloads and `filtre` criteria required in `Req*`, while shared pagination values such as `pageCourante` may remain optional. `FormInstance` belongs only to views and hooks: hooks extract the values before dispatch, and neither `Mdl*` nor `Ctrl*` receives a form. Hooks deliberately accept `Partial<Req*>` because router parameters complete the dispatched request. Do not add frontend `throw` guards for these values; backend validation remains authoritative. Result properties stay optional because each action populates only its subset, without `Res* | {}` unions.
- Generated controllers implement Waxant's `ActionOperation<Req, Res>` contract. Preserve typed form props and table rows, `_` prefixes on genuinely unused operation parameters, reducers without unused callback parameters, argument-free constant `toPath` functions, and empty ACLs without unused action imports.
- Keep API identifiers as `string` in domain models, services, form/reference values, account models, and URL parameters. The backend keeps `Long` internally and emits strings through `@JsonId`; do not introduce numeric coercion, `string | number`, or per-service ID mappers.
- Generated and runtime API services use normal TypeScript imports, not `import type`. The project intentionally has `verbatimModuleSyntax: false`, allowing TypeScript/Bun to erase their type-only usage.
- Generated and runtime Axios services put the payload type on the Axios call, use `const { data } = await ...`, return `data` separately, and infer async return types. Do not duplicate the same type with `Promise<T>` or write `return (await axios...).data`. Delete calls only await Axios. Keep mapped pagination access null-safe where the shared model is optional.
- Authentication uses `POST /api/login`, stores only `accessToken` in `sessionStorage`, derives `sub`, scalar `role`, and `exp` from the JWT, attaches bearer headers, and logs out on expiry or an authenticated `401`. Do not add refresh-token or `/api/user` assumptions.
- `ROLE_GESTIONNAIRE_RH` selects only HR modules; `ROLE_ADMIN` selects only account administration. Frontend ACLs hide UI but never replace backend authorization or create an implicit role hierarchy.
- HR APIs live under `/api/rh/**` and account administration under `/api/admin/accounts/**`. Department choices use `GET /api/rh/departements`. There is no generic `/api/rh/reference/**` API in the current backend; immutable reference choices must stay aligned with Liquibase data. Dates use `DD/MM/YYYY` in the UI and ISO `yyyy-MM-dd` on the wire. Current backend errors use `ApiError` with `code`, `message`, `path` and `fieldErrors`.
- `BUN_PUBLIC_API_URL` must include `/api`; `FRONTEND_PORT` configures the Bun server. `/app-config.json` may expose only non-secret resolved runtime configuration.
- Validate with `bun install --frozen-lockfile`, `bun run typecheck`, and `bun run build` as appropriate. Remove generated `dist/` after verification. Real-browser checks are useful, but do not claim full E2E while `../crud-e2e` remains a scaffold.
